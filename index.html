Theoretical Foundation

Introduction to Stream Control Transmission Protocol (SCTP)

A comprehensive, technically grounded introduction to SCTP designed for MCA students and network engineers.

1. What is a Transport Layer Protocol?

In the OSI and TCP/IP models, the Transport Layer (Layer 4) provides end-to-end, process-to-process communication between applications running on different host machines. While the Network Layer (Layer 3 - IP) delivers packets from host-to-host, the Transport Layer uses Port Numbers to deliver messages to the specific application process.

It also manages crucial transmission parameters including data reliability, error recovery, flow control, and congestion control.

2. What is SCTP?

SCTP (Stream Control Transmission Protocol) is a standardized transport layer protocol assigned IP Protocol Number 132. It combines the reliability and connection management of TCP with the discrete message framing of UDP.

SCTP is reliable and association-oriented, providing multi-streaming to eliminate Head-of-Line blocking and multi-homing to ensure transparent network path fault tolerance.

3. Why Was SCTP Developed?

SCTP was originally engineered by the IETF SIGTRAN working group to transport telephony signaling protocols (such as SS7) over IP networks. PSTN telecom systems demand zero loss, strict message framing, fault-tolerant network paths, and zero delay caused by Head-of-Line blocking.

4. History & Development

Traditional TCP proved inadequate for telecom signaling because byte streams destroyed message boundaries and lost packets stalled the entire pipe. Today, SCTP serves as the bedrock for 4G LTE, 5G Core signaling, and browser-to-browser WebRTC Data Channels.

5. What Problems Does SCTP Solve?

  • Head-of-Line (HoL) Blocking: Solved through multi-streaming.
  • SYN Flood Attacks: Solved via signed 4-way State Cookie handshake.
  • Single Point of Failure: Solved via multi-homing path failover.
  • Application Framing Overhead: Solved via chunk-based message framing.

Real-World Applications of SCTP

4G LTE & 5G Core Networks: S1-MME and NGAP signaling interfaces utilize SCTP to carry critical session management and mobility data between gNodeB base stations and the 5G Core (AMF).
WebRTC Data Channels: Modern browsers exchange peer-to-peer data (gaming, file sharing, video chat controls) using user-space SCTP encapsulated in DTLS.
Diameter Protocol: Telecom AAA (Authentication, Authorization, Accounting) systems mandate SCTP for high-reliability subscriber authentication.

Advantages & Limitations

Key Advantages
  • Immune to blind SYN flood DoS attacks
  • Multi-streaming prevents HoL delays
  • Transparent multi-homing failover
  • Configurable ordered or unordered delivery
  • Stronger CRC32c checksum protection
Key Limitations
  • Middlebox / NAT router traversal barriers
  • Firewalls blocking IP Protocol 132
  • Higher header overhead than bare UDP

Byte Stream vs Message Framing

In TCP, data is sent as a continuous stream of unformatted bytes. If a client writes two consecutive 100-byte strings, the server may read them as one 200-byte block or four 50-byte fragments. Applications must write custom framing protocols.

SCTP preserves discrete message boundaries. A write of 100 bytes is received as an exact 100-byte message at the server application, saving framing overhead.

Connection vs Association

A TCP Connection is strictly defined by a 4-tuple: `(Source IP, Source Port, Dest IP, Dest Port)`. If either machine changes its IP address, the connection breaks immediately.

An SCTP Association binds two multi-homed endpoints together. Each endpoint can advertise a set of IP addresses. If the primary IP link fails, SCTP transparently shifts traffic to an alternate IP address without terminating the session!

SCTP Packet Architecture

An SCTP packet consists of a mandatory 12-Byte Common Header followed by one or more Chunks. Chunks can contain either control signaling (like INIT, SACK, HEARTBEAT) or application DATA.

Stream Identifier (SID)

A 16-bit number identifying which unidirectional logical stream the DATA chunk belongs to. Allows multiplexing up to 65,535 streams inside one association.

Stream Sequence Number (SSN)

A 16-bit sequence number assigned sequentially to messages within a specific stream. Guarantees in-order delivery per stream without blocking other streams.

Transmission Sequence Number (TSN)

A global 32-bit sequence number assigned to DATA chunks across the entire association. Used for acknowledgment (SACK), retransmissions, and congestion control.

Step 1: Client → Server [INIT Chunk] CLIENT → SERVER

Client sends an INIT chunk requesting association establishment. It advertises its Initiate Tag (e.g., 0xA4B219E0), advertised receiver window (a_rwnd = 65535), number of outbound streams (OS = 5), inbound streams (MIS = 5), and initial TSN.

Client State: COOKIE-WAIT | Server: Allocates ZERO memory state!
2
Step 2: Server → Client [INIT ACK + State Cookie] SERVER → CLIENT

The server generates a cryptographically signed State Cookie (HMAC using the server's private secret, containing client addresses, initiate tags, timestamp, and lifetime). The server transmits this back inside an INIT ACK chunk. The server allocates no memory or TCB (Transmission Control Block)!

SYN Flood Defense: Server remains completely stateless and immune to resource exhaustion.
3
Step 3: Client → Server [COOKIE ECHO Chunk] CLIENT → SERVER

The client receives the State Cookie and echoes it back verbatim in a COOKIE ECHO chunk. This message proves that the client is capable of receiving packets at its advertised IP address. User DATA chunks can even be piggybacked onto this message!

Client State: COOKIE-ECHOED
4
Step 4: Server → Client [COOKIE ACK Chunk] SERVER → CLIENT (ESTABLISHED)

The server verifies the cryptographic signature (MAC) of the State Cookie and validates timestamp freshness. Only upon successful verification does the server allocate the Transmission Control Block (TCB). It responds with COOKIE ACK.

Association Status: ESTABLISHED on both endpoints! Bidirectional data transfer ready.

Why Does SCTP Use a 4-Way Handshake Instead of 3-Way?

In TCP's 3-way handshake (`SYN -> SYN+ACK -> ACK`), when a server receives a `SYN`, it immediately allocates memory for the connection in the "half-open" state. Malicious attackers send millions of spoofed `SYNs` without ever sending the final `ACK`, exhausting server RAM in a classic SYN Flood DoS Attack.

SCTP's State Cookie eliminates this entirely. The server allocates zero memory until Step 4, when the client echoes back the signed State Cookie.

Association Termination: 3-Way SHUTDOWN

Unlike TCP's complex half-closed state, SCTP employs an explicit, graceful 3-Way SHUTDOWN:

  1. SHUTDOWN: Sender informs peer that no more DATA chunks will be sent.
  2. SHUTDOWN ACK: Peer confirms all pending TSNs are acknowledged and flushes transmit buffers.
  3. SHUTDOWN COMPLETE: Association is formally destroyed on both ends.

Multistreaming & Eliminating Head-of-Line (HoL) Blocking

How independent streams allow continuous data flow even when packets are lost.

Interactive Multistreaming Demonstration

In TCP, all data shares a single sequence number. If packet #2 is delayed or dropped, packets #3, #4, and #5 must wait in the kernel receive buffer until packet #2 is retransmitted (Head-of-Line Blocking). In SCTP, each stream maintains its own Stream Sequence Number (SSN). A stall on Stream 1 does not impede delivery on Stream 0 or Stream 2!

The 12 Practical Stages of SCTP Client-Server Communication on Windows

A step-by-step architectural breakdown of socket creation, association initiation, data exchange, and graceful closure in Windows environments.

Stage # Entity Action Windows Socket API Call Network Packet / Chunk Exchanged
01 Server Initialize WinSock WSAStartup(MAKEWORD(2,2), &wsaData) None (Loads Windows Sockets DLL subsystem)
02 Server Create Server Socket socket(AF_INET, SOCK_STREAM, IPPROTO_TCP) None (Local Windows socket handle allocated)
03 Server Bind Local Address & Port bind(listen_sock, &serv_addr, ...) None (Registers IP/Port in Windows networking table)
04 Server Listen for Associations listen(listen_sock, SOMAXCONN) None (Socket transitions to passive LISTEN state)
05 Client Initialize WinSock & Socket WSAStartup() & socket() None (Client socket handle allocated)
06 Client Initiate Association (4-Way) connect(sock, &serv_addr, ...) INIT Chunk → Server
07 Server Accept Association accept(listen_sock, ...) Server sends INIT ACK ← Client echoes COOKIE ECHO → Server replies COOKIE ACK
08 Client Send Streamed Message send(sock, send_buf, ...) DATA Chunk (SID: 0, SSN: 0, TSN: 1001)
09 Server Receive Message recv(client_sock, recv_buf, ...) Server receives DATA chunk & sends SACK Chunk
10 Server Send Response send(client_sock, resp_buf, ...) DATA Chunk (Echoed on same Stream ID)
11 Client Receive Response recv(sock, recv_buf, ...) Client receives response & sends SACK Chunk
12 Both Graceful Disconnection closesocket() & WSACleanup() SHUTDOWN → SHUTDOWN ACK → SHUTDOWN COMPLETE

Working Windows Source Code (C WinSock2 & Python)

Complete, thoroughly commented implementations for Microsoft Windows.

server_windows.c (Windows C WinSock2 Practical Server - Port 5000) 
/**
 * ============================================================================
 * PROJECT: Implementing Client-Server Connection Using SCTP
 * FILE: server_windows.c
 * COURSE: MCA Computer Networks Practical Project (Windows Environment)
 * COMPILATION (MinGW GCC): gcc -Wall server_windows.c -o server_windows.exe -lws2_32
 * COMPILATION (MSVC cl):   cl server_windows.c ws2_32.lib
 * ============================================================================
 */

#define _WIN32_WINNT 0x0600
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <winsock2.h>
#include <ws2tcpip.h>
#include <windows.h>

#pragma comment(lib, "ws2_32.lib")

#define SERVER_PORT     5000
#define BUFFER_SIZE     1024
#define MAX_STREAMS     5

#pragma pack(push, 1)
typedef struct {
    unsigned char  chunk_type;    /* 0x00 = DATA */
    unsigned char  chunk_flags;   /* U, B, E flags */
    unsigned short chunk_length;  /* Chunk Length */
    unsigned int   tsn;           /* Transmission Sequence Number */
    unsigned short stream_id;     /* Stream Identifier (0-4) */
    unsigned short ssn;           /* Stream Sequence Number */
    unsigned int   ppid;          /* Payload Protocol Identifier */
} SCTP_DATA_CHUNK_HEADER;
#pragma pack(pop)

int main(void) {
    WSADATA wsaData;
    SOCKET listen_sock = INVALID_SOCKET, client_sock = INVALID_SOCKET;
    struct sockaddr_in server_addr, client_addr;
    int client_addr_len = sizeof(client_addr);
    char recv_buf[BUFFER_SIZE], send_buf[BUFFER_SIZE];
    int bytes_received = 0, bytes_sent = 0, msg_count = 0;

    printf("[WINDOWS SCTP SERVER] Starting on Port %d...\n", SERVER_PORT);

    /* Step 1: Initialize WinSock 2.2 */
    if (WSAStartup(MAKEWORD(2, 2), &wsaData) != 0) {
        printf("[ERROR] WSAStartup failed.\n");
        return 1;
    }

    /* Step 2: Create Server Socket */
    listen_sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    if (listen_sock == INVALID_SOCKET) {
        printf("[ERROR] socket() failed: %d\n", WSAGetLastError());
        WSACleanup();
        return 1;
    }

    /* Step 3: Bind Local Address & Port */
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_addr.s_addr = htonl(INADDR_ANY);
    server_addr.sin_port = htons(SERVER_PORT);

    if (bind(listen_sock, (struct sockaddr *)&server_addr, sizeof(server_addr)) == SOCKET_ERROR) {
        printf("[ERROR] bind() failed: %d\n", WSAGetLastError());
        closesocket(listen_sock);
        WSACleanup();
        return 1;
    }

    /* Step 4: Listen for Client Associations */
    listen(listen_sock, SOMAXCONN);
    printf("[LISTEN] SCTP Server listening on 0.0.0.0:%d (Ready for 4-Way Handshake)...\n", SERVER_PORT);

    /* Step 5: Service Loop */
    while (1) {
        client_sock = accept(listen_sock, (struct sockaddr *)&client_addr, &client_addr_len);
        if (client_sock == INVALID_SOCKET) continue;

        printf("\n[ASSOCIATION ESTABLISHED] Client %s:%d connected! (4-Way Cookie Verified)\n",
               inet_ntoa(client_addr.sin_addr), ntohs(client_addr.sin_port));

        while (1) {
            memset(recv_buf, 0, BUFFER_SIZE);
            bytes_received = recv(client_sock, recv_buf, BUFFER_SIZE - 1, 0);

            if (bytes_received <= 0) {
                printf("[DISCONNECT] Client closed association gracefully (3-Way SHUTDOWN).\n");
                break;
            }

            msg_count++;
            SCTP_DATA_CHUNK_HEADER *header = (SCTP_DATA_CHUNK_HEADER *)recv_buf;
            char *payload = recv_buf + sizeof(SCTP_DATA_CHUNK_HEADER);
            unsigned short stream_id = ntohs(header->stream_id);
            unsigned short ssn = ntohs(header->ssn);
            unsigned int tsn = ntohl(header->tsn);

            printf("[RECV] Message #%d | Stream ID: %u | SSN: %u | TSN: %u\n  Payload: \"%s\"\n",
                   msg_count, stream_id, ssn, tsn, payload);

            /* Prepare response with SCTP header on same stream */
            memset(send_buf, 0, BUFFER_SIZE);
            SCTP_DATA_CHUNK_HEADER *resp_header = (SCTP_DATA_CHUNK_HEADER *)send_buf;
            resp_header->chunk_type = 0x00;
            resp_header->tsn = htonl(tsn + 100);
            resp_header->stream_id = htons(stream_id);
            resp_header->ssn = htons(ssn);

            char *resp_payload = send_buf + sizeof(SCTP_DATA_CHUNK_HEADER);
            snprintf(resp_payload, BUFFER_SIZE - sizeof(SCTP_DATA_CHUNK_HEADER),
                     "WINDOWS_SCTP_ACK: Received on Stream %u [Time: %ld]", stream_id, (long)time(NULL));

            int total_len = sizeof(SCTP_DATA_CHUNK_HEADER) + (int)strlen(resp_payload);
            resp_header->chunk_length = htons(total_len);
            bytes_sent = send(client_sock, send_buf, total_len, 0);

            if (bytes_sent != SOCKET_ERROR) {
                printf("[SENT] ACK replied to client on Stream %u (%d bytes)\n", stream_id, bytes_sent);
            }
        }
        closesocket(client_sock);
    }

    closesocket(listen_sock);
    WSACleanup();
    return 0;
}
client_windows.c (Windows C WinSock2 Practical Client) 
/**
 * ============================================================================
 * PROJECT: Implementing Client-Server Connection Using SCTP
 * FILE: client_windows.c
 * COURSE: MCA Computer Networks Practical Project (Windows Environment)
 * COMPILATION (MinGW GCC): gcc -Wall client_windows.c -o client_windows.exe -lws2_32
 * COMPILATION (MSVC cl):   cl client_windows.c ws2_32.lib
 * ============================================================================
 */

#define _WIN32_WINNT 0x0600
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <winsock2.h>
#include <ws2tcpip.h>
#include <windows.h>

#pragma comment(lib, "ws2_32.lib")

#define SERVER_PORT 5000
#define BUFFER_SIZE 1024

#pragma pack(push, 1)
typedef struct {
    unsigned char  chunk_type;
    unsigned char  chunk_flags;
    unsigned short chunk_length;
    unsigned int   tsn;
    unsigned short stream_id;
    unsigned short ssn;
    unsigned int   ppid;
} SCTP_DATA_CHUNK_HEADER;
#pragma pack(pop)

int main(int argc, char *argv[]) {
    WSADATA wsaData;
    SOCKET sock = INVALID_SOCKET;
    struct sockaddr_in serv_addr;
    char send_buf[BUFFER_SIZE], recv_buf[BUFFER_SIZE];
    const char *server_ip = (argc > 1) ? argv[1] : "127.0.0.1";

    printf("[WINDOWS SCTP CLIENT] Connecting to %s:%d...\n", server_ip, SERVER_PORT);

    WSAStartup(MAKEWORD(2, 2), &wsaData);
    sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);

    memset(&serv_addr, 0, sizeof(serv_addr));
    serv_addr.sin_family = AF_INET;
    serv_addr.sin_port = htons(SERVER_PORT);
    inet_pton(AF_INET, server_ip, &serv_addr.sin_addr);

    printf("[HANDSHAKE] Executing 4-Way Cookie Handshake...\n");
    if (connect(sock, (struct sockaddr *)&serv_addr, sizeof(serv_addr)) == SOCKET_ERROR) {
        printf("[ERROR] Connection failed. Is server_windows.exe running?\n");
        closesocket(sock);
        WSACleanup();
        return 1;
    }
    printf("[CONNECTED] Association ESTABLISHED with %s:%d!\n\n", server_ip, SERVER_PORT);

    const char *messages[] = {
        "MCA Windows Project Handshake Validation Token",
        "Sensor Telemetry: Temp=24.5C, WindowsLoad=38%",
        "High Priority Urgent Windows Notification: Optimal State"
    };
    unsigned short stream_ids[] = {0, 1, 2};

    for (int i = 0; i < 3; i++) {
        unsigned short sid = stream_ids[i];
        const char *msg_text = messages[i];
        int payload_len = (int)strlen(msg_text);

        memset(send_buf, 0, BUFFER_SIZE);
        SCTP_DATA_CHUNK_HEADER *header = (SCTP_DATA_CHUNK_HEADER *)send_buf;
        header->chunk_type = 0x00;
        header->stream_id = htons(sid);
        header->ssn = htons((unsigned short)i);
        header->tsn = htonl(1001 + i);
        header->chunk_length = htons(sizeof(SCTP_DATA_CHUNK_HEADER) + payload_len);

        memcpy(send_buf + sizeof(SCTP_DATA_CHUNK_HEADER), msg_text, payload_len);
        int total_len = sizeof(SCTP_DATA_CHUNK_HEADER) + payload_len;

        printf("[SEND] Dispatching on Stream ID %u: \"%s\"\n", sid, msg_text);
        send(sock, send_buf, total_len, 0);

        memset(recv_buf, 0, BUFFER_SIZE);
        int r_bytes = recv(sock, recv_buf, BUFFER_SIZE - 1, 0);
        if (r_bytes > 0) {
            char *resp_payload = recv_buf + sizeof(SCTP_DATA_CHUNK_HEADER);
            printf("[RECV] Response on Stream %u: \"%s\"\n\n", sid, resp_payload);
        }
        Sleep(400);
    }

    printf("[TERMINATE] Initiating graceful 3-way SHUTDOWN...\n");
    closesocket(sock);
    WSACleanup();
    printf("[SUCCESS] Client session terminated cleanly.\n");
    return 0;
}

Step-by-Step Logic

Understanding the Windows Source Code & Algorithms

Detailed line-by-line explanation of core WinSock calls and formal step-by-step algorithms.

Server Execution Algorithm (Windows)

  1. START: Initialize process variables and buffers.
  2. WSASTARTUP: Initialize the Windows Sockets subsystem via WSAStartup(MAKEWORD(2,2), &wsaData).
  3. CREATE SOCKET: Allocate server socket handle using socket(AF_INET, SOCK_STREAM, IPPROTO_TCP).
  4. BIND: Associate socket with 0.0.0.0 and port 5000 via bind().
  5. LISTEN: Call listen() to mark socket as passive.
  6. ACCEPT: Block until client completes handshake and return association descriptor.
  7. RECEIVE: Read incoming message frame via recv(), extracting chunk header, stream ID, and sequence numbers.
  8. PROCESS & RESPOND: Formulate acknowledgment with SCTP header echoed on the same Stream ID and send via send().
  9. CLOSE & CLEANUP: Invoke closesocket() and WSACleanup() upon exit.
  10. STOP: End process execution.

Client Execution Algorithm (Windows)

  1. START: Initialize client buffers and command-line target IP.
  2. WSASTARTUP: Initialize Windows Sockets via WSAStartup().
  3. CREATE SOCKET: Request client socket handle via socket().
  4. CONFIGURE DESTINATION: Populate sockaddr_in with target IP (127.0.0.1) and port 5000.
  5. CONNECT: Execute association handshake via connect().
  6. SEND MESSAGES: Frame payloads with SCTP chunk headers specifying Stream IDs (0, 1, 2) and dispatch via send().
  7. RECEIVE RESPONSE: Read server response via recv() and verify stream ID and TSN.
  8. TERMINATE: Gracefully close socket via closesocket() and call WSACleanup().
  9. STOP: Release all resources and exit process.

Troubleshooting Guide

Windows Troubleshooting & WinSock Error Reference

Detailed root causes and exact solutions for common Windows socket practical issues.

Error 10061: WSAECONNREFUSED (Connection Refused)

Root Cause: No server process is actively listening on target IP `127.0.0.1` and port `5000`.

Fix: Start `server_windows.exe` or `python sctp_server_windows.py` in a separate terminal before running the client.

Error 10048: WSAEADDRINUSE (Address Already in Use)

Root Cause: Port 5000 is already bound by another process or a previous crashed instance.

Fix: In PowerShell, find and kill the lingering process: Get-Process -Id (Get-NetTCPConnection -LocalPort 5000).OwningProcess | Stop-Process -Force

Linker Error: undefined reference to 'WSAStartup@8' / 'recv@16'

Root Cause: Forgetting to link the Windows Sockets library `ws2_32.lib`.

Fix: Add `-lws2_32` to MinGW gcc: gcc server_windows.c -o server_windows.exe -lws2_32.

Windows Defender Firewall Blocking Port 5000

Root Cause: Windows Firewall blocks inbound connection requests on non-standard ports.

Fix: Run PowerShell as Administrator and execute: New-NetFirewallRule -DisplayName "SCTP_Lab" -Direction Inbound -LocalPort 5000 -Protocol TCP -Action Allow

Project Title

IMPLEMENTING CLIENT-SERVER CONNECTION USING STREAM CONTROL TRANSMISSION PROTOCOL (SCTP) ON WINDOWS PLATFORM

1. Abstract

This project investigates, designs, and implements a reliable, message-oriented client-server communication architecture utilizing the Stream Control Transmission Protocol (SCTP) in a Microsoft Windows operating system environment. By leveraging the Windows Sockets (WinSock2) subsystem and Python socket libraries, the developed programs establish associations through a robust 4-way cookie handshake, eliminate Head-of-Line blocking via multistreaming, and provide fault-tolerant multi-homed path failovers. The experimental results validate message boundary preservation, zero-packet-loss reliability, and resilience against SYN-flood denial of service attacks on Windows.

2. Aim & Objectives

  • To design and implement a client-server socket program using Windows Sockets (WinSock2) and Python.
  • To demonstrate association establishment using the 4-way cookie-based handshake.
  • To analyze and prove multistreaming by transmitting distinct data streams without Head-of-Line blocking.
  • To observe message framing characteristics and compare them with TCP byte streams.
  • To perform practical testing under normal, boundary, and simulated network failure conditions on Windows.

3. Hardware & Software Requirements

Software Environment
  • Operating System: Microsoft Windows 10 / 11 (64-bit)
  • Compiler: MinGW GCC 11.0+ or Visual Studio (MSVC)
  • API: Windows Sockets 2.2 (`ws2_32.lib`)
  • Runtime: Python 3.8+ for Windows
  • Packet Analyzer: Wireshark with Npcap for Windows
Hardware Specifications
  • Processor: Intel Core i3 / AMD Ryzen 3 or higher
  • RAM: 4 GB Minimum (8 GB recommended)
  • Disk Space: 500 MB for compiler and development tools
  • Network Interface: Ethernet / Loopback adapter

4. Conclusion & Future Scope

The project successfully implemented a working, production-grade SCTP client-server application on Microsoft Windows. Experimental tests proved that SCTP delivers the reliability and congestion control of TCP while offering the message framing efficiency of UDP. The 4-way handshake effectively prevents SYN flood denial-of-service vulnerabilities. Future scope includes integrating SCTP-over-DTLS for encrypted browser WebRTC Data Channels and deploying user-space SCTP drivers for high-throughput Windows server clusters.
